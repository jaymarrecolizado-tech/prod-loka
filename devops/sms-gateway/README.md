# LOKA SMS Gateway setup

Outbound SMS for travel participants via [SMS Gateway for Android](https://github.com/capcom6/android-sms-gateway).

## Path A — Local test (this PC + your phone) — recommended first

Easiest local mode uses the **phone as the API server** (no Docker required).

1. Install [SMS Gateway APK](https://github.com/capcom6/android-sms-gateway/releases) (use **Insecure** build only if you need cleartext HTTP on LAN).
2. On the phone: enable **Local Server**, grant SMS permissions, tap Online/Start.
3. Note the LAN IP, port (usually `8080`), username, and password shown in the app.
4. PC and phone on the **same Wi‑Fi**. Allow firewall if needed.
5. In LOKA (All Father → System Control → **SMS**):
   - Enable SMS
   - Gateway URL: `http://PHONE_LAN_IP:8080`
   - API path: **Local phone server** (`/message`)
   - Username / password from the app
   - Save → Send test SMS → Process queue if needed
6. Run migration once: `php public_html/migrations/023_sms_notifications.php`
7. Optional cron: `php public_html/cron/process_sms_queue.php` every 1–2 minutes (or use **Process queue now**).

LOKA on XAMPP calls the phone; the phone sends SMS via the SIM.

## Path B — Docker private server (Hostinger / advanced local)

Official private server image: `ghcr.io/android-sms-gateway/server:latest`  
See: https://docs.sms-gate.app/getting-started/private-server/

Summary:

1. VPS with Docker + MySQL database for the gateway
2. `config.yml` with `gateway.mode: private` and a private token
3. Nginx + HTTPS for `sms.yourdomain.com`
4. Android app → Cloud/Private server → API URL `https://sms.yourdomain.com/api/mobile/v1` + private token
5. In LOKA SMS settings:
   - Gateway URL: `https://sms.yourdomain.com`
   - API path: **Private / Hostinger** (`/api/3rdparty/v1/messages`)
   - Username/password generated by the app after it connects

`docker-compose.example.yml` in this folder is a starting point — adjust DB passwords and domain before use.

## Safety

- Keep SMS **disabled** until gateway credentials are set.
- Never commit real passwords.
- Approvals/dispatch still work if SMS fails (soft-fail queue).
